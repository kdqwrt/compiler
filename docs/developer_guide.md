# Руководство разработчика MiniCompiler

## 1. Назначение документа

Данный документ описывает внутреннюю архитектуру MiniCompiler и порядок разработки новых возможностей.

MiniCompiler — учебный компилятор для упрощённого C-подобного языка. Проект реализован на Python и включает полный конвейер компиляции: от чтения исходного файла до генерации ассемблера, объектного файла и исполняемой программы.

---

# 2. Общий конвейер компиляции

Компиляция выполняется по следующей схеме:

```text
Исходный код
  ↓
Препроцессор
  ↓
Лексический анализатор
  ↓
Синтаксический анализатор
  ↓
AST
  ↓
Семантический анализатор
  ↓
IR
  ↓
Оптимизации IR
  ↓
Генерация x86-64 ASM
  ↓
Peephole-оптимизация ASM
  ↓
NASM
  ↓
Объектный файл
  ↓
GCC/Linker
  ↓
Исполняемый файл
```

---

# 3. Основные модули проекта

## 3.1. Препроцессор

Назначение:

- удаление комментариев;
- обработка простых директив;
- подготовка текста программы к лексическому анализу.

Типовые возможности:

```text
// однострочный комментарий
/* многострочный комментарий */
#define
#undef
```

---

## 3.2. Лексический анализатор

Лексер преобразует исходный текст в последовательность токенов.

Он отвечает за:

- ключевые слова;
- идентификаторы;
- литералы;
- операторы;
- разделители;
- строки и колонки токенов;
- часть лексических ошибок.

Примеры токенов:

```text
fn
main
(
)
int
return
+
-
*
/
```

---

## 3.3. Парсер

Парсер получает токены и строит AST.

Он обрабатывает:

- объявления функций;
- объявления переменных;
- структуры;
- блоки;
- условия;
- циклы;
- выражения;
- вызовы функций;
- обращения к массивам;
- обращения к полям структур.

---

## 3.4. AST

AST — абстрактное синтаксическое дерево.

Оно хранит структуру программы в виде узлов.

AST используется для:

- семантического анализа;
- вывода в text / JSON / DOT;
- построения IR;
- хранения аннотаций после семантического анализа.

В AST дополнительно сохраняются:

```text
inferred_type
symbol
constant_value
line
column
```

Эти данные используются на последующих этапах.

---

## 3.5. Семантический анализатор

Семантический анализатор проверяет смысловую корректность программы.

Проверяются:

- повторные объявления;
- использование необъявленных имён;
- использование переменной до объявления;
- использование неинициализированной переменной;
- соответствие типов;
- корректность условий;
- корректность вызовов функций;
- корректность возвращаемого значения;
- корректность операций присваивания.

Пример ошибки:

```c
fn main() -> int {
    int x;
    return x;
}
```

Диагностика:

```text
variable 'x' may be used before initialization
```

---

## 3.6. Таблица символов

Таблица символов хранит информацию об именах.

Поддерживаются области видимости:

```text
global
function
block
struct
```

В таблице символов хранятся:

- переменные;
- функции;
- параметры;
- структуры;
- поля структур;
- типы;
- порядок объявления;
- информация о видимости.

---

## 3.7. IR

IR — промежуточное представление программы.

Оно находится между AST и ассемблером.

IR нужен для:

- упрощения генерации кода;
- оптимизаций;
- тестирования;
- анализа последовательности операций.

Основные инструкции IR:

```text
MOVE
ADD
SUB
MUL
DIV
LOAD
STORE
GEP
PARAM
CALL
RETURN
CMP_EQ
CMP_NE
CMP_LT
CMP_LE
CMP_GT
CMP_GE
JUMP
JUMP_IF
JUMP_IF_NOT
ALLOCA
MEMCPY
ADDR_OF
```

Пример IR:

```text
PARAM 0, 8
arr = CALL malloc
t1 = MOVE 14
STORE x, 14
RETURN x
```

---

# 4. Генерация IR

IR строится на основе AST.

Основные правила:

- объявление обычной локальной переменной создаёт `ALLOCA`;
- объявление локального массива создаёт вызов `malloc`;
- доступ к массиву создаёт `GEP`;
- вызов функции создаёт `PARAM` и `CALL`;
- возврат значения создаёт `RETURN`.

---

## 4.1. Обычные переменные

Пример:

```c
int x = 5;
```

IR:

```text
x = ALLOCA 4
STORE x, 5
```

---

## 4.2. Массивы

Пример:

```c
int arr[2];
```

IR:

```text
PARAM 0, 8
arr = CALL malloc
```

Размер считается так:

```text
sizeof(int) * 2 = 4 * 2 = 8 байт
```

На стеке хранится только указатель на массив.

---

## 4.3. Доступ к массиву

Пример:

```c
arr[1] = 7;
```

IR:

```text
GEP arr, 4
STORE [addr], 7
```

Адрес элемента считается так:

```text
base + index * sizeof(type)
```

Для `arr[1]`:

```text
base + 1 * 4
```

---

# 5. Генерация x86-64 ASM

Генератор ассемблера преобразует IR в NASM-compatible x86-64 код.

Поддерживаются:

- секция `.text`;
- секция `.rodata`;
- секция `.data`;
- секция `.bss`;
- внешние функции;
- локальные переменные;
- временные значения;
- массивы;
- указатели;
- вызовы функций;
- возврат значения;
- debug-директивы `%line`.

---

## 5.1. Внешние функции

В ASM объявляются внешние функции:

```asm
extern printf
extern scanf
extern malloc
extern free
extern strlen
extern pow
```

Они вызываются через:

```asm
call printf
call malloc
call strlen
```

---

## 5.2. Соглашение System V AMD64 ABI

Аргументы передаются через регистры:

```text
1 аргумент -> rdi
2 аргумент -> rsi
3 аргумент -> rdx
4 аргумент -> rcx
5 аргумент -> r8
6 аргумент -> r9
```

Результат функции возвращается через:

```text
rax
```

Для вещественных значений используются SSE-регистры:

```text
xmm0
xmm1
```

---

## 5.3. Пример malloc

Исходный код:

```c
int arr[2];
```

ASM:

```asm
mov rdi, 8
call malloc
mov qword [rbp-8], rax
```

Объяснение:

- `rdi = 8` — размер выделяемой памяти;
- `call malloc` — вызов внешней функции;
- `rax` — адрес выделенной памяти;
- `[rbp-8]` — стековая ячейка, где хранится указатель на массив.

---

## 5.4. Пример printf

Исходный код:

```c
printf("x=%d\n", x);
```

ASM:

```asm
lea rdi, [rel __str_0]
mov esi, r12d
xor eax, eax
call printf
```

Объяснение:

- `rdi` — адрес строки формата;
- `esi` — значение для `%d`;
- `xor eax, eax` — подготовка к вызову variadic-функции;
- `call printf` — вызов функции из libc.

---

# 6. Модель памяти

Используются следующие области памяти:

```text
стек
куча
.rodata
.data
.bss
```

---

## 6.1. Стек

На стеке хранятся:

- обычные локальные переменные;
- временные значения;
- указатели на массивы;
- сохранённые callee-saved регистры.

---

## 6.2. Куча

В куче размещаются локальные массивы.

Пример:

```c
int arr[2];
```

Выделяется:

```text
malloc(8)
```

---

## 6.3. .rodata

В `.rodata` размещаются:

- строковые литералы;
- вещественные константы.

Пример:

```asm
section .rodata
__str_0: db 'x', '=', '%', 'd', 10, 0
```

---

## 6.4. .data

В `.data` размещаются инициализированные глобальные переменные.

---

## 6.5. .bss

В `.bss` размещаются неинициализированные глобальные переменные.

---

# 7. Register Allocation

В проекте реализован linear scan register allocation.

Включается флагом:

```bash
--use-register-allocation
```

Используются регистры:

```text
r12
r13
```

Для переменных типа `int` используются 32-битные части:

```text
r12d
r13d
```

Пример:

```asm
mov r12d, 14
```

`r12d` означает младшие 32 бита регистра `r12`.

---

## 7.1. Сохранение callee-saved регистров

Так как `r12` и `r13` являются callee-saved, компилятор сохраняет их в начале функции:

```asm
mov qword [rbp-104], r12
```

и восстанавливает перед выходом:

```asm
mov r12, qword [rbp-104]
```

Это нужно для соблюдения ABI.

# 8. Оптимизации

В проекте реализован набор базовых оптимизаций.

---

## 8.1. Constant Folding

Свёртка констант.

Пример:

```c
int x = 2 + 3 * 4;
```

После оптимизации:

```text
x = 14
```

---

## 8.2. Constant Propagation

Распространение известных констант.

Если известно, что:

```c
int x = 14;
```

то последующие обращения могут использовать значение `14`.

---

## 8.3. Dead Code Elimination

Удаление недостижимого кода.

Пример:

```c
return 0;
x = 5;
```

Код после `return` удаляется.

---

## 8.4. Dead Store Elimination

Удаление бесполезных записей.

Пример:

```c
int unused = 100;
```

Если переменная не используется, запись может быть удалена.

---

## 8.5. Control Flow Simplification

Упрощение переходов и условий.

Пример:

```asm
jmp .L1
.L1:
```

Такой переход может быть удалён.

---

## 8.6. Peephole Optimization

После генерации ASM запускается peephole-оптимизатор.

Размер окна:

```text
5 инструкций
```

Он анализирует локальные шаблоны и удаляет лишние инструкции.

Примеры:

```asm
mov eax, eax
```

может быть удалено.

```asm
add eax, 0
```

может быть удалено.

---

## 8.7. Compile-time bounds check для массивов

Если индекс массива является константой и компилятор может доказать, что он корректен, runtime-проверка границ не генерируется.

Пример:

```c
arr[0] = 14;
```

Если размер массива равен 2, индекс `0` корректен.

Поэтому лишний runtime-код вида:

```asm
cmp eax, 0
jl bounds_fail
cmp eax, 2
jge bounds_fail
```

может быть не сгенерирован.

# 9. Debug information

В проекте реализована передача location-информации из AST в IR и дальше в ASM.

Для NASM используется директива:

```asm
%line 4 input.src
```

При сборке с debug-информацией:

```bash
nasm -g -F dwarf
```

формируется DWARF line information.

Проверка:

```bash
readelf --debug-dump=decodedline file.o
```

# 12. Тестирование

Используются следующие виды тестирования:

```text
unit tests
golden tests
integration tests
regression tests
differential tests
property-based tests
fuzz tests
debug/DWARF tests
```

---

## 12.1. Golden tests

Golden tests сравнивают фактический вывод с эталонным.

Проверяются:

- IR;
- diagnostics;
- ASM;
- debug output.

---

## 12.2. Integration tests

Integration tests проверяют полный конвейер:

```text
source -> IR -> ASM -> object -> executable
```

---

## 12.3. Differential tests

Differential tests сравнивают результат работы MiniCompiler и GCC на эквивалентных простых программах.

Сравниваются:

- stdout;
- exit code.

---

## 12.4. Property-based tests

Property-based tests проверяют свойство:

```text
оптимизация не должна менять наблюдаемое поведение программы
```

То есть программа без оптимизации и с оптимизацией должна давать одинаковый результат.

---

## 12.5. Fuzz tests

Fuzz tests подают на вход случайные некорректные программы.

Цель:

```text
компилятор не должен падать с traceback
```

Он должен завершаться контролируемо и выводить ошибку.

# 14. Добавление новой внешней функции

Чтобы добавить новую внешнюю функцию, нужно:

1. добавить её сигнатуру в семантическую систему;
2. разрешить вызов в анализаторе;
3. добавить `extern` в генератор ASM;
4. при необходимости добавить особую передачу аргументов;
5. добавить тест.

Пример уже поддержанных функций:

```text
printf
scanf
malloc
free
strlen
pow
```

---

# 15. Добавление новой IR-инструкции

Порядок добавления:

1. добавить opcode в список IR-инструкций;
2. добавить текстовое и JSON-представление;
3. добавить генерацию инструкции в IRGenerator;
4. добавить обработку в x86_generator;
5. при необходимости добавить оптимизацию;
6. добавить тесты.

---

# 16. Добавление новой оптимизации

Порядок добавления:

1. определить уровень оптимизации;
2. реализовать pass;
3. подключить pass к pipeline;
4. добавить golden tests;
5. добавить property-based или integration test;
6. проверить, что поведение программы не изменилось.

# 19. Ограничения

MiniCompiler является учебным компилятором.

Ограничения:

- не реализует весь язык C;
- оптимизации не являются аналогом GCC/Clang;
- поддерживается ограниченный набор стандартных функций;
- генерация кода ориентирована на x86-64 Linux;
- основная сборка выполняется через NASM и GCC;
- часть возможностей Windows используется через отдельные команды или WSL.
