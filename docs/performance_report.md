# Отчёт по измерению производительности MiniCompiler

## 1. Цель исследования

Целью исследования является оценка производительности программ, сгенерированных компилятором MiniCompiler, а также анализ влияния реализованных оптимизаций на характеристики получаемого исполняемого кода.

В рамках исследования были проведены измерения времени выполнения, использования памяти и размера исполняемого файла. Дополнительно была выполнена попытка получения аппаратных счётчиков производительности при помощи инструмента `perf`.

---

# 2. Тестовая среда

Измерения выполнялись в следующей среде:

```text
Операционная система: Ubuntu Linux
Архитектура: x86-64
Компилятор: MiniCompiler
Ассемблер: NASM
Компоновщик: GCC
```

---

# 3. Тестовая программа

В качестве тестовой программы использовался пример:

```text
examples/profile_fib.src
```

Программа вычисляет число Фибоначчи рекурсивным способом.

Ожидаемый результат работы:

```text
fib=6765
```

Использование рекурсии позволяет создать заметную нагрузку на стек вызовов и проверить корректность работы генератора кода, механизма вызова функций и соглашения System V AMD64 ABI.

---

# 4. Методика измерений

Были собраны две версии программы.

Без оптимизаций:

```bash
python -m src.cli examples/profile_fib.src -o fib_noopt_program
```

С оптимизациями:

```bash
python -m src.cli examples/profile_fib.src -o fib_opt_program --optimize
```

Измерения производились при помощи следующих инструментов:

```bash
/usr/bin/time -v
size
perf stat
```

# 8. Ограничения измерений perf

Во время работы инструмента `perf` были обнаружены ограничения операционной системы:

```text
perf_event_paranoid = 4
```

Вследствие этого аппаратные счётчики процессора оказались недоступны.

В частности, не удалось получить значения:

```text
cycles
instructions
IPC
branch-misses
```

Поэтому расчёт показателя IPC (Instructions Per Cycle) выполнен не был.

Отсутствие этих данных связано с настройками безопасности операционной системы и не связано с работой компилятора или сгенерированной программы.

# 9. Анализ результатов

Проверка показала, что обе версии программы корректно вычисляют число Фибоначчи и завершаются с кодом возврата 0.

Сравнение показало:

- одинаковый размер исполняемого файла;
- одинаковое потребление памяти;
- близкие значения времени выполнения.

Полученные результаты объясняются тем, что тестовая программа является небольшой и большая часть времени затрачивается на рекурсивные вызовы функций. На подобных программах влияние локальных оптимизаций обычно выражено незначительно.

В проекте реализованы следующие оптимизации:

- Constant Folding;
- Constant Propagation;
- Dead Code Elimination;
- Dead Store Elimination;
- Control Flow Simplification;
- Register Allocation;
- Peephole Optimization.

Для небольших программ их эффект может быть практически незаметен на уровне общего времени выполнения, однако они позволяют уменьшить количество лишних инструкций и обращений к памяти.

# 10. Вывод

В ходе исследования была проведена оценка производительности программ, сгенерированных компилятором MiniCompiler.

Проверено корректное выполнение программы с рекурсивными вызовами функций. Измерены характеристики времени выполнения, использования памяти и размера исполняемого файла.

Результаты показали, что компилятор генерирует работоспособный исполняемый код для архитектуры x86-64 и обеспечивает корректную работу функций, рекурсии, соглашения вызовов System V AMD64 ABI и механизма компоновки с внешними библиотеками.

Проведённые измерения подтвердили корректность работы оптимизационного конвейера и отсутствие влияния оптимизаций на наблюдаемое поведение программы.


# 11. Дополнительная проверка видимости оптимизаций

Для демонстрации влияния оптимизаций была использована отдельная программа:

```text
examples/perf_opt_visible.src
```

Программа содержит:

- константные арифметические выражения;
- массив, выделяемый через `malloc`;
- обращение к элементам массива;
- вызов `printf`;
- неиспользуемую переменную;
- операции, которые могут быть упрощены оптимизатором.

---

## 11.1. Проверка IR до и после оптимизации

Команды:

```bash
python -m src.cli examples/perf_opt_visible.src --ir > perf_noopt.ir
python -m src.cli examples/perf_opt_visible.src --ir --optimize > perf_opt.ir
diff -u perf_noopt.ir perf_opt.ir
```

В IR без оптимизации присутствовали арифметические инструкции:

```text
t1 = MUL 3, 4
t2 = ADD 2, t1
STORE x, t2
```

После оптимизации они были заменены на заранее вычисленные значения:

```text
t1 = MOVE 12
t2 = MOVE 14
STORE x, 14
```

Также выражение:

```text
10 * 2
```

было свёрнуто до:

```text
20
```

Это демонстрирует работу оптимизации Constant Folding.

---

## 11.2. Проверка ASM до и после оптимизации

Команды:

```bash
python -m src.cli examples/perf_opt_visible.src -S -o perf_noopt.asm

python -m src.cli compile \
  --input examples/perf_opt_visible.src \
  --output perf_opt.asm \
  --optimize \
  --use-register-allocation

diff -u perf_noopt.asm perf_opt.asm
```

В оптимизированной версии видно использование регистрового аллокатора:

```asm
mov r12d, 14
mov r13d, r12d
```

В не оптимизированной версии значения чаще сохранялись во временные стековые ячейки вида:

```asm
mov dword [rbp-24], eax
mov dword [rbp-28], eax
```

Таким образом, оптимизированная версия уменьшает количество обращений к стеку и использует регистры для хранения локальных значений.

---

## 11.3. Проверка одинакового поведения

Команды:

```bash
./perf_noopt_program
echo $?

./perf_opt_program
echo $?
```

Результат:

```text
result=14
14
result=14
14
```

Обе версии программы имеют одинаковое наблюдаемое поведение. Это подтверждает, что оптимизации не изменили результат выполнения программы.

Код возврата `14` является ожидаемым, так как программа возвращает значение `arr[0]`.

---

## 11.4. Сравнение размера исполняемых файлов

Команды:

```bash
size perf_noopt_program
size perf_opt_program
```

Результаты:

| Версия | text | data | bss | Итого |
|--------|------|------|-----|-------|
| Без оптимизаций | 1252 байта | 552 байта | 8 байт | 1812 байт |
| С оптимизациями | 1201 байт | 552 байта | 8 байт | 1761 байт |

После включения оптимизаций размер секции `text` уменьшился на 51 байт.

Общий размер исполняемого файла по секциям уменьшился с 1812 до 1761 байта.

---

## 11.5. Вывод по дополнительной проверке

На программе `perf_opt_visible.src` влияние оптимизаций видно явно:

- константные выражения были вычислены заранее;
- часть временных стековых операций была устранена;
- регистровый аллокатор разместил значения в регистрах `r12d` и `r13d`;
- размер секции кода уменьшился;
- поведение программы осталось неизменным.

Данный пример лучше подходит для демонстрации оптимизаций, чем рекурсивная программа Фибоначчи, так как содержит простые конструкции, на которых хорошо видны Constant Folding, Register Allocation и уменьшение количества лишних инструкций.
